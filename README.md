# VulnWatch · 漏洞情报监控系统

> **Vuln**（漏洞）+ **Watch**（守望）= 帮你 24 小时盯着服务器、数据库、办公软件有没有新漏洞，一有新漏洞就自动发消息提醒你。

一个**零门槛、开箱即用**的安全公告监控工具。它默认每 10 分钟自动去各大官方渠道（微软、NVD、CISA、Go、群晖……）和国内安全社区（长亭、奇安信、微步、Seebug……）抓最新的漏洞情报，按严重程度打分，然后把你该关心的**高危漏洞**自动推送到钉钉群，其他的一律存起来，随时在网页上翻看。

---

> **v0.3.1**：新增自动检测 / 自动推送独立开关、安静模式、高危合并窗口与历史公告过滤，强化跨源 CVE 去重。详见 [CHANGELOG.md](CHANGELOG.md)。这是公告聚合工具，产品关键词匹配不等于已确认你的资产存在漏洞。

## 一句话说清楚它是干嘛的

> 你公司有 200 台电脑、6 台服务器、一堆数据库和中间件，你不可能天天自己去翻各个厂商的安全公告。**VulnWatch 替你做这件事**——定期检查公告，采集到符合条件的新高危漏洞后立即提醒。

## 核心功能

### 1. 多源自动采集（28 个源）

| 类别 | 监控对象 | 数据来源 |
|------|----------|----------|
| 🖥️ 操作系统 | Windows Server / Linux 内核 | NVD + MSRC |
| 💾 数据库 | MySQL / PostgreSQL / SQL Server / Redis / MongoDB / Oracle | NVD |
| 🌐 Web 服务器 | IIS / Nginx / Apache / Struts2 | NVD + 厂商公告 |
| 📦 NAS | 群晖 DSM / QNAP | 厂商公告页 |
| 🖧 虚拟化 | VMware ESXi / vCenter | NVD |
| 🔧 语言运行时 | Go / Node.js / Python / OpenJDK | Go OSV + NVD |
| 🚨 在野利用 | CISA KEV（正被攻击的漏洞） | CISA 官方 |
| 🇨🇳 国内情报 | 长亭 / OSCS / 奇安信 / 微步 / Seebug / Struts2 | 官方 API |
| 🇨🇳 国内情报(可选) | 阿里云 AVD / 启明星辰 | 需装 Playwright |

> 国内源借鉴了开源项目 [watchvuln](https://github.com/zema1/watchvuln) 的采集思路，专门补足「国外 NVD 覆盖不到的国产软件漏洞」。

采集性能（v0.2.0 起）：

- **NVD 批量模式**：15 个 NVD 源不再各查一次，而是按时间范围一次拉全量、本地按关键词过滤，请求数从 15 次降到 1~3 次；
- **多源并行采集**：默认 8 个线程并发（`VULNWATCH_COLLECT_WORKERS` 可调）；
- **批量入库**：一次采集只提交一次事务，而不是一条漏洞一次 commit；
- **手动采集改为后台任务**：页面立即返回、实时显示每个源的进度，不会因为代理超时白等。

### 2. 智能分级 + 精准推送

- 按 **CVSS 评分**分成 5 档：严重 / 高危 / 中危 / 低危 / 未知
- **在野利用（KEV）漏洞无条件置顶**，🚨 高亮，且跨源去重时优先保留 KEV 记录
- 支持**产品关键词黑白名单**——只看你公司真正在用的产品，其他全过滤掉
- 支持**标签过滤**——只看带「POC公开」「预警」等标记的，精准命中
- **跨源去重**——同一个 CVE 从多个源抓到，只推最严重（KEV 优先）的那一条
- **静默时段**——普通告警可延期；严重 / KEV 默认突破静默（可关闭），按业务时区判断
- **首次采集不轰炸**——每个源首次成功采集只建历史基线；采集失败不会提前建立基线
- **持久化待推送记录**——符合即时阈值的失败或静默延期内容每分钟检查重试，其他内容留给每日汇总；同一 CVE 跨天去重，后续升级为 KEV 可再提醒一次
- **报告自动分条**——默认覆盖全部符合条件的记录；单条内容过长时截短展示，完整内容可在网页查看

### 3. 多渠道通知

- ✅ **钉钉机器人**（默认，支持加签，最常用）
- ✅ **企业微信 / 飞书 / Server酱 / PushPlus**，在配置页切换即可，无需改代码
- 每次推送（成功/失败/静默/跳过/基线）都会记一条 AlertLog，排查问题有据可查

### 4. Web 管理界面

网页上就能完成所有操作，不用碰命令行：
- 查看漏洞列表、按等级/关键词/KEV/时间筛选，展示 AI 摘要
- 弹窗新增、编辑监控源，支持取消与 Esc 关闭
- 配置通知渠道、阈值、黑白名单、静默时段、每日推送时间（保存即生效，无需重启）
- 手动触发「立即检测并告警」（后台执行 + 实时进度）
- 概览「手动推送」先预览剩余待推送；漏洞列表每条记录可重发历史记录
- 概览显示检测间隔、下次执行时间、待推送数量和运行状态
- 一键「发送测试消息」验证推送是否通
- 查看每个源最近一次采集结果和最近推送日志，重启后仍保留

### 5. 安全加固

- 可选**访问口令**（`VULNWATCH_AUTH_TOKEN`），支持 `Authorization: Bearer`、HTTP Basic、`?token=` 三种方式
- 访问口令可放在 URL 里首次打开（`http://ip:8000/?token=xxx`），页面会自动存入 localStorage 并从地址栏抹掉
- 内置安全响应头（CSP / X-Frame-Options / nosniff 等），401 响应同样带安全头
- 所有列表渲染对 CVE 号、标题、来源等字段做 HTML 转义（防存储型 XSS）
- `/api/health`、页面和 `/static/*` 静态资源公开（页面本身不含数据，浏览器加载脚本也无法附带头）；其余数据接口在设置口令后一律需要认证
- 口令保存在 localStorage 中，刷新页面或收藏地址都不会失效
- API 数据响应带 `Cache-Control: no-store`，避免共享终端缓存

## 检测、推送与 DeepSeek 的完整逻辑

| 场景 | 默认行为 |
|---|---|
| 周期检测 | 可独立开关，默认每 10 分钟；网页可设 5–1440 分钟，与手动采集互斥 |
| 即时告警 | 安静模式：严重 / KEV 立即通知，普通高危等每日汇总；可切为高危合并提醒 |
| 静默时段 | 默认关闭；启用后普通高危延期，严重 / KEV 默认仍通知 |
| 发送失败 | 只确认成功部分，每分钟检查待推送内容；跨源和分片统一限速 |
| 每日汇总 | 09:00 / Asia/Shanghai，默认汇总剩余高危及以上，不重复已发送记录 |
| 自动推送总开关 | 关闭后暂停即时告警和每日汇总，保留队列；手动发送仍可用 |
| 高危合并窗口 | 可设 0–60 分钟；高危也即时提醒时默认合并 5 分钟，到期一起发送，严重 / KEV 不等待 |
| 历史公告过滤 | 默认 7 天：发布早于首次入库超过 7 天的公告仅入库，KEV 例外；0 表示不限 |
| 手动待推送 | 概览「手动推送」→ 预览 → 确认发送，遵守过滤条件，忽略静默 |
| 手动指定记录 | 列表「推送」→ 预览 → 确认发送，允许重发历史记录，忽略过滤与静默 |

首次成功采集作为历史基线，不自动轰炸旧公告。即时不是外部网站发布瞬间的事件订阅：实际时延受检测间隔、网络耗时、来源覆盖和更新速度影响。没有资产探针，不会扫描公司设备。通道接收成功但进程在落回执前退出时仍可能重复，不能承诺严格只投递一次。


### 开关、合并与去重的边界

- 定时检测开关关闭后，不再创建后续采集任务，已开始的一轮会完成；自动推送开关负责暂停即时告警及日报，两者独立。手动操作仍可使用。
- 配置页最上方有三种快捷方案：安静模式（推荐）、高危合并提醒、仅每日汇总。点击方案即保存，其他字段需点击保存。
- 合并窗口以最早待发送普通高危的首次入库时间计算；窗口内后来的高危一起发送，不不断延后到期时间，重启后仍保留。严重 / KEV 按原即时策略处理。
- 同一 CVE 统一去除首尾空白并转为大写，跨源、跨轮、重启后共享持久回执。无 CVE 按来源及公告标识去重，不按相似标题合并，以免漏掉不同漏洞。
- 已经成功推送的普通漏洞随后列入 KEV，默认再提醒一次，配置页可关闭；首次历史基线的漏洞后来新增 KEV 仍属新风险。手动指定记录可主动重发。
- 历史过滤比较「公告发布日期」与「首次入库时间」，而不是与当前时间比较，因此失败、静默或暂停多日的合格告警仍然会重试。没有发布日期的记录按新发现处理，旧 CVE 新增 KEV 不受历史过滤限制。

### DeepSeek 增强做什么？

把**公开公告**整理为中文「风险、受影响范围、建议操作」，不负责采集、分级或判断你的服务器是否受影响。只发送这一条公告的公开字段，不附带监控配置、Webhook、服务器凭据或内部资产清单。

1. 先发送原始告警，紧急通知不等待 AI。
2. 每分钟后台挑选已经成功推送、尚无摘要的记录，默认每轮最多 5 条、每天最多 20 次调用。按业务时区计数，重启不清零。
3. 摘要缓存到漏洞列表，同一 CVE 跨源复用；之后手动重发附带已有摘要，不为摘要单独再发通知。
4. 首次历史基线不批量解读；历史记录经手动推送后可以进入解读队列。失败消耗一次预算，至少一小时后重试。
5. 无 Key、关闭开关、达到限额或失败时，采集与推送照常。默认无 Key 时关闭，需要填 Key 并启用；按自己的 DeepSeek 账号计费，次数上限不等于金额上限。

默认模型 `deepseek-flash`，网页可改。使用官方 [Chat Completion API](https://api-docs.deepseek.com/api/create-chat-completion/)，关闭思考模式、限制响应长度和超时。模型输出供辅助阅读，补丁与受影响版本以原始官方公告为准。

### 运行期配置与接口

网页保存即生效：`collect_enabled`、`notifications_enabled`、`instant_batch_minutes`、`alert_max_age_days`、`notify_kev_upgrade`、`collect_interval_minutes`、`instant_enabled`、`instant_threshold`、`urgent_bypass_silent`、`daily_enabled`、`daily_time`、`ai_enabled`、`ai_model`、`ai_daily_limit`、`ai_batch_limit`。

- `GET /api/runtime`：策略、下次执行时间和脱敏 AI 状态。
- `POST /api/notifications/preview`：`{"mode":"pending"}` 或 `{"mode":"selected","ids":[123]}`；不写回执，指定记录最多 50 个 ID。
- `POST /api/notifications/send`：相同请求体；202 表示后台已开始，409 表示推送任务冲突。
- `GET /api/notifications/status`：本进程最近手动任务；持久化日志见 `GET /api/alerts`。

这些接口使用已有口令认证。即时、每日、手动推送共用回执与互斥锁。网页操作先预览再确认。

## 快速开始（本地试用，2 分钟）

需要 Python 3.11+，推荐 Python 3.12。

```bash
# 1. 创建虚拟环境（隔离依赖，避免污染系统）
python -m venv venv
source venv/bin/activate        # Windows 用：venv\Scripts\activate

# 2. 安装依赖
pip install -r requirements.txt

# 3. 启动（首次运行会自动建数据库 + 内置 28 个默认源）
python run.py
```

浏览器打开 **http://127.0.0.1:8000**，就能看到管理界面了。

> 第一次打开时漏洞列表可能是空的，点一下「立即检测并告警」按钮，任务会在后台跑，页面上能看到每个源的进度；首轮只建历史基线不推送。

> Windows 上如果启动报 `ZoneInfoNotFoundError`，`pip install tzdata` 即可（requirements.txt 已包含）。

### 想先自检一遍？（可选）

项目自带离线冒烟测试（不访问任何外部网站，约 10 秒）：

```bash
pip install -r requirements-dev.txt   # 额外的测试依赖（httpx）
python scripts/smoke_test.py
python tests/test_reliability.py
```

它会检查：模块导入、13 种采集器注册、全部 HTTP 接口（健康检查 / 监控源增删改查 / 漏洞列表 / 统计 / 配置读写）、批量入库幂等与 AI 摘要保留、日报分片、调度辅助函数、参数校验。退出码 `0` 表示全部通过。

## 部署到服务器（正式使用）

完整教程见 **[DEPLOY.md](DEPLOY.md)**，这里给最常用的两条路：

> ⚠️ **必须以单进程（单 worker）运行**：APScheduler 和 SQLite 都在进程内。多 worker 会导致定时任务被重复注册、SQLite 锁竞争。Dockerfile / systemd / compose 里都已固定 `--workers 1`。

### 方式一：Docker（推荐，最省心）

```bash
# 上传代码到服务器后
cd /opt/vulnwatch
export VULNWATCH_AUTH_TOKEN=$(openssl rand -hex 16)   # 建议设置访问口令
docker compose up -d --build                          # 构建并后台启动
docker compose logs -f vulnwatch                      # 看日志
```

浏览器打开 `http://服务器IP:8000`。容器内置 healthcheck（调用 `/api/health`），`docker ps` 可直接看到健康状态。

> 首次部署可先 `cp .env.example .env`，按注释填写访问口令、时区等；compose 会自动读取 `.env`，无需 `export`。

### 方式二：systemd（开机自启 + 长期运行）

请按 [DEPLOY.md](DEPLOY.md) 的 systemd 步骤部署：使用专用 `vulnwatch` 用户、`/opt/vulnwatch/.venv` 虚拟环境和 `/var/lib/vulnwatch` 数据目录。访问口令放在权限为 `600` 的 `.env` 中。

服务默认只监听 `127.0.0.1:8000`。直接供局域网访问时，在 `.env` 设置 `VULNWATCH_HOST=服务器内网IP`；使用反向代理时保留默认值。旧版升级需先迁移数据目录，不能只替换服务文件。

## 配置说明

### 环境变量（进程级，改完需重启）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `VULNWATCH_AUTH_TOKEN` | 空 | 访问口令；留空=匿名访问 |
| `VULNWATCH_DATA_DIR` | `./data` | 数据目录（SQLite 与备份） |
| `VULNWATCH_DB` | `data/vulnwatch.db` | 数据库文件路径 |
| `VULNWATCH_TIMEZONE` | `Asia/Shanghai` | 业务时区（定时任务/静默/报告时间） |
| `VULNWATCH_DAILY_HOUR` / `_MINUTE` | `9` / `0` | 每日汇总时间（周期采集独立；网页 `daily_time` 覆盖它） |
| `VULNWATCH_COLLECT_WORKERS` | `8` | 并行采集线程数，慢网可降到 2~4 |
| `VULNWATCH_REQUEST_INTERVAL` | `1.0` | 同一域名请求最小间隔（秒） |
| `VULNWATCH_RETRY_TIMES` | `2` | 单次请求网络失败的重试次数 |
| `VULNWATCH_NVD_BULK` | `1` | NVD 批量模式开关（一次拉取最近 N 天全量，供所有 NVD 源本地过滤） |
| `VULNWATCH_NVD_DAYS` | `7` | NVD 批量拉取最近天数 |
| `VULNWATCH_NVD_INTERVAL` | `6.0` | NVD 请求间隔（官方无 key 建议 ≥6 秒） |
| `VULNWATCH_NVD_CACHE_TTL` | `600` | NVD 批量结果进程内缓存秒数 |
| `VULNWATCH_OSV_CONCURRENCY` | `6` | Go 官方漏洞库详情并发数 |
| `VULNWATCH_PUSH_MAX_BYTES` | `3600` | 单条消息字节上限（超长自动分条） |
| `VULNWATCH_AI_MODEL` / `_AI_SUMMARY_LIMIT` | `deepseek-flash` / `5` | 默认解读模型与每轮条数；网页配置可覆盖 |

### 配置页（存数据库，保存即生效）

第一步：配置钉钉推送

1. 打开钉钉群 → 右上角「群设置」→「智能群助手」→「添加机器人」→「自定义机器人」
2. 安全设置选 **「加签」**（最稳妥，不用设关键词），记下 **Webhook 地址** 和 **加签密钥(Secret)**
3. 打开 VulnWatch 网页 →「配置」→ 填入这两项 → 点「发送测试消息」，钉钉群收到消息就成功了 ✅

第二步：设置推送阈值

在「配置」页选推送等级，默认「高危及以上」：
- **仅严重**：只推最紧急的
- **高危及以上**（推荐）：严重 + 高危
- **中危及以上 / 全部**：推得更多，也更吵

> KEV 绕过等级阈值，但仍受产品关键词和标签筛选影响。首次历史基线和已发送内容不会再次自动发送。

第三步（强烈建议）：设置访问口令

部署到公网或多人环境前，务必设一个访问口令，防止别人看到你的监控数据：

```bash
# Docker：用 .env 文件（docker compose 会自动读取）
echo "VULNWATCH_AUTH_TOKEN=你的随机口令" > .env

# systemd：写 /opt/vulnwatch/.env（service 已配置 EnvironmentFile）
```

口令建议用 `openssl rand -hex 16` 生成一段随机串。设置后首次访问用 `http://服务器IP:8000/?token=口令` 打开即可。

## 日常维护教程

### 每天要做的事

默认每 10 分钟检测，严重 / KEV 采集后即时通知；普通高危在每天 09:00 汇总，不发空日报。概览可以暂停 / 恢复定时检测或自动推送。

### 每周/偶尔看一眼

| 事项 | 操作 |
|------|------|
| 看有没有采集失败的源 | 网页「监控源」页，点「采集」单独重试 |
| 备份数据库 | 使用 SQLite 在线备份脚本（见下方命令） |
| 更新系统 | 先备份，再按 [DEPLOY.md](DEPLOY.md) 更新依赖并重启 |

### 备份与恢复

```bash
# systemd：在线备份并校验完整性
sudo /opt/vulnwatch/.venv/bin/python /opt/vulnwatch/scripts/backup.py

# 本地运行：指定数据库和输出目录
python scripts/backup.py --database data/vulnwatch.db --directory backups
```

SQLite 的 WAL 模式不能保证直接复制运行中的数据库得到一致备份。请使用上面的脚本；恢复需先停止服务，具体步骤见 [DEPLOY.md](DEPLOY.md)。数据库和备份包含通知凭证，应限制访问。

### 常见问题

**Q: 某个源一直采集到 0 条？**
A: 先检查最近采集状态。成功但为 0 可能是近期无匹配记录；也可能是网站结构或筛选条件变化。失败时查看错误，不要把 HTTP 403 等错误当成没有漏洞。

**Q: 首次部署推了一大堆历史漏洞？**
A: 每个源首次成功采集只建立历史基线、不推送；之后的新记录按即时或每日策略处理，历史回填另受时效过滤。0.2.1 及以上升级均保留现有基线与回执；更早版本首次引入回执表时才需要重新建基线。

**Q: 想改每天推送的时间？**
A: 直接去「配置」→「每日汇总」改每天时间，保存即生效；也可以用环境变量 `VULNWATCH_DAILY_HOUR` / `VULNWATCH_DAILY_MINUTE`（仅当数据库里没有 `daily_time` 时生效）。

**Q: 钉钉/企微提示消息太长发送失败？**
A: 已经按 `VULNWATCH_PUSH_MAX_BYTES`（默认 3600 字节）自动分条；如仍失败可再调小。

**Q: 采集很慢？**
A: 默认并行 8 个源 + NVD 批量模式，正常 10~60 秒。慢网环境把 `VULNWATCH_COLLECT_WORKERS` 调到 2~4，并适当加大 `VULNWATCH_NVD_INTERVAL`。

## 历史优化（v0.2.0）

详见 **[OPTIMIZATION.md](OPTIMIZATION.md)**。一句话总结：

- 修复 NVD 请求间隔被重复叠加（每请求约 12 秒）的问题，并改为批量拉取；
- 修复全局锁内 sleep 导致所有域名串行的问题；
- 单条漏洞 commit → 批量 upsert（一次采集的事务数从 ~2800 降到 1）；
- Go OSV 详情从串行 60 次请求改为 6 路并发；
- 手动采集改为后台任务 + 进度轮询，解决同步阻塞/网关超时；
- 报告按通道字节上限自动分条，超长不再被截断；
- 静默时段/定时任务改用业务时区，不再依赖服务器本地时间；
- 跨源去重优先保留 KEV 记录（原来可能丢掉在野利用标记）；
- 首次采集建立基线不推送、AlertLog 全量记录，与文档行为一致；
- 修复漏洞列表 CVE 号未转义的存储型 XSS；
- 修复安全响应头在 401 响应上缺失、Docker 镜像缺 tzdata、compose 废弃 version 字段等问题；
- 补齐 README 中宣称但未落地的能力（AI 摘要、基线、daily_time 网页可改）。
